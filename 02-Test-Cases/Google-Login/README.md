## Why Both Excel and Markdown Versions Exist

Test scenarios and test cases were first drafted in Microsoft Excel — a
common real-world QA workflow — then documented in Markdown for clean
version control and readability on GitHub. Both are kept here to show the
complete process, from initial drafting through to polished documentation.

---

## Scope

This exercise focuses on a **login flow modeled on Google's account login**
(email step → password step, "Show Password," Forgot Password, 2FA prompt).
It is a test design exercise, not an execution against Google's live
production system — all test cases are documented with status
**Not Executed**, reflecting that this demonstrates test planning and
design skill rather than claiming actual execution results.

---

## Skills Demonstrated

- Test scenario identification from a feature description
- Deriving detailed test cases from high-level scenarios
- Positive, negative, validation, security, and compatibility test design
- Structured test case documentation (preconditions, steps, test data, expected result)
- Drafting in Excel and formalizing in Markdown for a GitHub-based QA portfolio
